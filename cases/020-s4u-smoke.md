# 案例：S4U 无人值守推送的实证

> 脱敏说明：任务名、主机、路径、提交哈希、日期均已移除。数字仅保留与结论相关的类型。

## 问题

计划任务注册为 S4U 之后，脚本每天能跑，但「跑成功」不等于「推送成功」。
需要在不等待定时触发的前提下，证明三件事：

1. 任务真的执行了脚本；
2. 脚本在 S4U 上下文里能找到 git 与 ssh；
3. 推送确实发生了，而不是「仓库已是最新」的假阳性。

## 一个关键的判读陷阱

在一个干净、已与远端同步的仓库上直接触发备份，脚本会走
「无需提交、无需推送」分支，最终状态是 `push=uptodate`。
这是**正确**的结果，但它完全没有执行 `git push`。
把 `uptodate` 当成「推送通过」，是这类验证里最常见的误判。

正确做法：先制造至少一个未推送的提交，再触发任务，然后同时核对：

- 状态文件里 `push` 为 `ok`；
- 本地 `HEAD` 与 `origin` 同点；
- 该提交由脚本自己产生，而不是测试前手工留下的。

## 冒烟结果

- 触发命令返回成功，无 UAC 拦截；任务的上次运行结果码为 0。
- 状态文件被重写（时间戳更新），`local_status=ok`，`push=ok`。
- 本地 HEAD 与远端同点。
- 另有一个更早的成功快照留在状态文件里，因此**必须先比对时间戳**，
  否则旧的成功记录会被误读成本次通过。

## 三处提示文本的缺陷

注册脚本末尾打印的冒烟测试命令有三处问题，都不影响功能，但都会误导人：

1. **字符串拼接缺括号**：PowerShell 里 `Write-Host 'a' + $x + 'b'` 会先输出 `a`
   再输出两个字符串相加的结果，多出一个 `+` 号。必须用括号包住整个表达式。
2. **`findstr "Result"` 在中文系统零命中**：列名被本地化，
   命令输出为空，看起来像「任务从未运行」。
   改用 `Get-ScheduledTaskInfo | fl LastRunTime,LastTaskResult,NextRunTime`，
   它返回对象属性而不是本地化文本。
3. **章节号指向错误**：提示里让人去看的章节不存在。提示文本也要复核。

## 一次被权限层拦下的替代方案

原计划用一个空提交制造待推送状态。仓库里有一个陈旧的 `index.lock`，
`git commit` 直接失败；尝试把它移走时又被权限层以「敏感文件」拦下。
没有绕过权限层，而是改用**等价方案**：工作区本来就有本次修复的改动，
让备份脚本自己产生一个真实提交。判定条件完全相同，
差别只在于待推送的是修复本身而不是空提交。

副产品：那个陈旧锁在 S4U 运行中被脚本的锁自愈逻辑处理掉了，
为「索引锁自愈」这个设计再加一例证。

## 方法要点

- 验证「推送」时，必须能区分 `ok` / `failed` / `blocked` / `uptodate` 四种状态。
- 冒烟测试要排除旧状态文件的干扰：比对时间戳，而不是只看字段值。
- 权限层拒绝时，记录拒绝本身，并寻找等价路径；不要用更高权限硬来。
